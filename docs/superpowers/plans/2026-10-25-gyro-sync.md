# Built-in SenseFlow A1 Gyro Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** mlv2Resolve writes, for every mounted MLV clip covered by a SenseFlow A1 log, a synced `.gyroflow` next to the MLV (lens profile + mounting position + offsets), replacing NiYien Tool.

**Architecture:** A new C command-line tool `mlvmotion` (built from the engine's LJ92 decoder, FFT via Accelerate) extracts per-frame image motion from an MLV. The Swift core parses A1 logs, preselects a log by clocks, solves the offset by gyro↔motion regression, builds a computed lens profile and writes the `.gyroflow`. A coordinator in `AppState` runs it in the background per mounted shoot; the window and Settings expose lenses, position and per-clip state.

**Tech Stack:** C (engine, Accelerate vDSP), Swift 6 / SwiftUI, XCTest, Python PoC (`poc/`) as reference only.

**Spec:** `docs/specs/2026-10-25-gyro-sync-design.md`

## Global Constraints

- Never write, rename or delete MLV files or A1 logs; never create cut log files (exception allowed only by Task 1's fallback: one full-length `.gcsv` per log, next to the log).
- `.gyroflow` written directly in the shoot's source folder (not through the mount), named `<clip folder name>_000000.gyroflow` (e.g. `M24-1845MLV_1_2026-10-24_0001_C0000_000000.gyroflow`).
- Never overwrite an existing `.gyroflow` unless the user asked (Regenerate, or a lens/position change on that clip); before replacing, copy the old file to `~/Library/Application Support/mlv2Resolve/gyroflow-backups/<shoot>/<name>-<yyyyMMdd-HHmmss>.gyroflow`.
- `offsets` format (validated): keys = gyro timestamp µs as integer string = round((videoMs − offsetMs) × 1000); values = offsetMs (Double). Write 3 points at 15 %, 50 %, 85 % of the clip duration.
- `synchronization.do_autosync = false`; `gyro_source.filepath` = `file://` URL of the full log; `videofile` = `file://` URL of `<mount>/<clipdir>/<clipdir>_%06d.dng` percent-encoded (the `%` of `%06d` becomes `%25`).
- Target plugin/app: Gyroflow (NiYien) 1.6.3 (project `version` 3, `app_version` "1.5.4" as NiYien writes).
- Lenses are user data (no hard-coded list). Default mounting position Top → `gyro_source.imu_orientation = "XYZ"`, `rotation = [0,0,0]`.
- Test data `~/Desktop/Tests mlv2Resolve/Test Gyroflow` (M24-1843/1844/1845.MLV, `2026-10-24_18-44-03_mix.bin`, `…18-44-15…`, `…18-44-36…`) is read-only; tests use it only when `MLV2Resolve_GYRO_DIR` is set (skip otherwise). Never commit MLVs, logs, or files with personal paths.
- UI strings EN + FR (app String Catalog, core `.strings`). Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A shoot whose camera clock is days off (seen: 55 days) → still synced by motion search over all logs of the folder; never a wrong confident match (Task 5 test `testHugeClockSkewStillMatchesOrRefuses`).
2. A clip only partly covered by a log (log starts or stops mid-clip) → synced if the overlap ≥ 8 s or ≥ 80 % of the clip, else « no log covers this clip » (Task 4 test `testPartialOverlap`).
3. A still/locked-off clip (no motion) → refused with « not enough camera motion », no file written (Task 4 test `testNoMotionRefused`).
4. Unplugging the disk or unmounting during a background sync → job cancelled cleanly, no partial `.gyroflow` (atomic temp + rename) (Task 8 test `testCancelOnUnmountLeavesNoFile`).
5. Two logs overlapping in time (A1 restarted) → the best-scoring one is used and recorded in the state (Task 8 test `testOverlappingLogsPickBest`).

### Task 4: Offset solver (Swift)

**Files:** Create `app/Sources/MLV2ResolveCore/GyroSync.swift`; Test `app/Tests/MLV2ResolveCoreTests/GyroSyncTests.swift`

**Interfaces:**
- Produces:
  ```swift
  public struct MotionSample: Sendable { public let frame: Int; public let dx: Double; public let dy: Double; public let peak: Double }
  public struct SyncResult: Sendable, Equatable { public let lagMs: Int /* first frame's time in the log */; public let r2: Double; public let secondPeak: Double; public let map: [[Double]] /* 3×2 */ }
  public enum SyncRefusal: Error, Equatable { case notEnoughMotion, noOverlap, ambiguous(r2: Double, second: Double) }
  public enum GyroSync { public static func solve(motion: [MotionSample], fps: Double, gyro: [SIMD3<Float>], rateHz: Double, searchMs: ClosedRange<Int>) throws -> SyncResult }
  ```
  Algorithm = `poc/sync_gyro.py` (cumulative-sum gyro, per-frame rotation increments, least squares with intercept, drop the 10 % lowest-peak frames, coarse 10 ms step then ±15 ms at 1 ms, secondPeak = best R² with |lag − best| > 500 ms). Use vDSP/Accelerate for the normal equations. Accept iff r2 ≥ 0.35 AND r2 − secondPeak ≥ 0.15 AND motion RMS ≥ 1.0 px/frame (thresholds from measured cases 0.56/0.315, 0.666/0.315, 0.783/0.234 vs no-log 0.094/0.080); overlap rule = Review Focus 2 (lags whose window leaves the log are scored on the covered part only).
- [ ] **Step 1: Tests:** `testRecoversSyntheticLag` (random-walk gyro, motion = known 3×2 map × integrated gyro shifted by 4192 ms + noise σ=0.5 px) → lagMs 4192 ± 1, r2 > 0.9; `testNoMotionRefused` (constant motion) → `.notEnoughMotion`; `testNoiseIsAmbiguous` (motion independent of gyro) → `.ambiguous`; `testPartialOverlap` (log covers the last 9 s of a 12 s clip) → accepted; covers 5 s → `.noOverlap`; gated `testRealM24_1845` (mlvmotion output + real log) → lagMs 4192 ± 10, r2 ≈ 0.78 ± 0.05.
- [ ] **Step 2:** FAIL. **Step 3:** Implement. **Step 4:** PASS. **Step 5:** Commit `feat(core): gyro/motion offset solver`.
